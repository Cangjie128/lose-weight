# V2.1 今日实际饮食修复

日期：2026-11-03。基准：`593e465`。分支：`codex/v2-1-daily-coach`。

## 根因与保存链路

- `QuickMealForm` 已经调用 `saveMeal`，后者更新 `data.meals` 并等待 IndexedDB 保存；照片另行写入 IndexedDB，完成后才关闭新增弹窗并回首页。新回归测试直接读取 `records/current` 和照片关联确认这条链路。
- 首页 `DailyCoachHome` 只渲染 `snapshot.mealTasks`（推荐），遗漏了 `snapshot.meals`（实际）。此前“首页看不到”不能据此判断记录未保存。
- 删除餐食原来只移除记录，没有调用实际饮食调整逻辑，可能留下旧的自动建议。本轮一起修复。

## 本轮修改

1. 新增独立“今日实际饮食”，按早餐、午餐、晚餐、加餐展示真实 `data.meals` 当天记录，即使资料尚未确认也可查看。
2. 展示食物名称、份量、实际照片、热量区间、蛋白质/脂肪/碳水及备注。未知营养明确待补充，使用与每日累计相同的确定性函数，不将推荐值或未知值当摄入。
3. 各餐次没有记录时显示“尚未记录”和新增入口，入口预选正确餐次；每条记录可打开现有编辑弹窗。
4. 首页和历史详情共用实际饮食组件，避免名称、营养或照片显示不一致。新建返回首页立即显示，编辑也即时更新，无需切换页面。
5. 原“三餐安排”改为“今日推荐饮食”，保留推荐但明确不计入实际摄入。只有明确保存或确认实际按菜单进食才新增真实餐食，浏览/生成计划不写入摄入。
6. 下一餐选择排除已记录的餐次；实际饮食保存和删除均重算累计和后续自动建议。删除后清除旧自动菜单选择，不覆盖完成、跳过、手动调整及历史计划。
7. 删除需确认，成功后关闭对应编辑弹窗；取消删除保留记录。原始照片文件继续保留，不自动清理。
8. 新增当前地址和端口隔离提示。3007、3008、3009 的 IndexedDB 各自独立，换端口需用户用完整 ZIP 手动导入，不自动迁移。

## 预览与数据安全

- 原数据地址的修复版：[http://127.0.0.1:3008/](http://127.0.0.1:3008/)。只替换本地服务进程，没有清除浏览器存储，刷新即可让新版读取这个地址原有的记录。
- 新独立预览：[http://127.0.0.1:3009/](http://127.0.0.1:3009/)。这里不会自动出现 3007/3008 的记录；空白不是记录丢失。
- 3007 继续保持旧版对照，不修改其代码或数据。
- 独立 `.next-actual-meals` 构建避免覆盖旧运行构建；默认回环监听且清空外部数据库/AI/Google 凭证，不允许付费 AI 模式。
- `npm run preview:actual-meals` 可重新构建并启动默认 3009；指定端口使用 `PREVIEW_PORT`。端口占用时以实际启动输出为准。

旧行动教练测试将“替换后的菜单编号”写死为 1，本轮改为从当前编号循环到下一组，并继续验证内容确实变化及用户手动状态；真实饮食触发自动推荐后，起始编号不一定是 0。没有因此修改业务菜单去迎合固定断言。

测试使用独立 Chromium 上下文与合成数据/照片。没有对用户现有记录执行自动化增删改，也没有启用真实模型、连接生产数据库、部署 Oracle、修改 main 或合并 PR。依赖版本和锁文件未变。
