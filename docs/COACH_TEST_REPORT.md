## 本轮交付

本地预览：[http://127.0.0.1:3007/](http://127.0.0.1:3007/)。重新启动使用 `npm run preview:coach`；若端口占用以启动输出为准。独立 `.next-coach` 构建、独立端口、只监听本机，清空外部服务配置。未访问生产服务器、未部署、未合并 main，未读取或清空用户原有浏览器数据，也未中断 3005 预览。

### 本轮试用反馈修复

- 餐食分析支持纯文字、照片加文字及一餐多种食物；逐项保存食物、份量状态和营养估算。份量不可靠时标为待确认，整餐不计入确定性累计，避免把未知值当作零。
- 默认预览仍为零外部请求。只有显式使用 `npm run preview:coach:ai` 并在服务端环境配置 `DEEPSEEK_API_KEY` 才开启回环地址测试接口；接口限制来源、请求大小、图片数、调用间隔、每日次数、输出 Tokens 和超时，不重试、不调用 OpenAI。
- 首页新增显眼的“记录今日体重”，趋势页新增快捷入口；输入默认空白，同日保存更新原记录。体重、餐食、运动和身体状态会调整未完成的未来任务，保留完成、跳过、历史及用户手改任务。
- 餐食保存后立即重算每日营养和下一餐建议；低蛋白时优先给出蛋白质来源，同时保留主食和蔬菜，不以运动惩罚饮食。
- 所有可见的“拾光计划”与“SHIGUANG”已统一为“减肥计划”或“我的减肥计划”。内部旧数据库命名保持不变，以免破坏历史数据和备份兼容性。

### 首页设计

首页顺序为品牌和日期、今日/本周/复盘切换、七日日期条、安全边界、行动进度与下一项、具体下一餐、按时间排列的行动。体重和身体记录、营养详情降为可展开的次级内容。

每项行动展示时间、份量或时长、强度、步骤、安排理由、完成标准及官方学习资料。支持完成、跳过、稍后/跨日调整；餐食支持替换与拍照；训练可改为恢复。手机优先，桌面保留侧边导航，320px 也可访问。

新用户从没有历史记录的真实空状态开始，自动获得当前周一至周日的 49 项安排：每日三餐、可选加餐、运动/恢复、饮水、睡眠。没有用示例体重冒充用户历史。未填写年龄时仅提供参考份量，不宣称已有个人减脂热量处方。

### 确定性生成逻辑

1. 读取身高、体重、年龄、活动量、目标日期、饮食偏好、过敏/不喜欢食物、准备条件、运动设备、时间和身体限制。
2. 复用营养目标函数，不调用模型。份量以目标能量的早餐 26%、午餐 32%、晚餐 32%、可选加餐 10% 为参考；无目标时使用明确标注的通用参考份量。食物库为粗估，不是品牌标签或专业营养数据库。
3. 每餐提供最多三组可替换组合，注明干/熟重或可食部分；所有候选都经过食物限制筛选。无法组成安全主餐时要求用户确认，不记作已摄入。
4. 根据每周运动次数和条件安排步行/入门力量，力量日不相邻，至少保留两个恢复日。身体限制、近期不适、睡眠不足或疲劳触发保守恢复，而不是用运动抵消饮食。
5. 周计划和任务 ID 稳定，调整保存在单独执行记录中；重排不改写原始身份。用户确认调整本周时保留已完成、已跳过和手工调整的任务及全部实际记录。
6. 完成餐食可只标记任务；只有勾选确实按菜单进食才写入粗估营养。改变份量后禁止沿用旧估计；只改时间则不失去原菜单参考。拍照保存实际文件与任务关联，不自动调用识别，也不虚构未知营养。
7. 实际餐食汇总影响下一餐具体组合；未知营养先提示补充。热量较高也不建议跳餐或加练。用户手工修改的下一餐份量优先显示，不被旧菜单悄悄替代。
8. 每周复盘依据已确认执行、实际运动、疲劳和不适生成下一周；必要时缩短训练，不自动减少热量，不将漏记当作禁食，不覆盖已经存在的下一周。

## 尚未验收

- 最终架构明确为用户 Oracle Cloud 完全自托管，不使用 Supabase。已提交独立 PostgreSQL DDL、服务契约与 [架构设计](SELF_HOSTED_ARCHITECTURE.md)，但账号服务、HTTP API、私有文件适配器和双设备同步尚未实现，不能直接当作生产后端部署。
- DeepSeek 真实模型视觉能力、模型名/账号可用性、识别准确度、真实额度错误需配置服务并接通新认证后验收。本轮本地模式关闭付费入口；没有发出真实请求，也未自动调用 OpenAI。无 Key 的基础功能已通过。
- Google/MCP 的旧授权和只读逻辑保留回归测试，但需要迁移至新账号体系；当前未向 Google 同步，也没有宣称接通 ChatGPT。
- 通用食物词过滤不能确保复杂配料或交叉接触安全。严重过敏、疾病、孕哺及持续疼痛需专业指导，不能把参考菜单当作医疗处方。
- 尚未进行实体手机摄像头/低内存设备、macOS 实体机解压或真实用户长期依从性测试。浏览器视口测试不是物理设备认证。
- 2026-10-28 的 `npm audit --omit=dev` 另报告 `body-parser`、`fast-uri`、`qs` 与 `zod` 共 4 项新告警，来源为 MCP SDK、React Server/Webpack 链及项目直接依赖。为遵守“仅做必要 Next.js 安全补丁、不顺带大范围升级”的约束，本轮未运行自动升级；需在独立安全分支评估兼容性后处理。

等待用户试用首页、菜单和任务节奏后，再决定后续后端实现与部署安排。保持 Draft，不合并、不部署。
