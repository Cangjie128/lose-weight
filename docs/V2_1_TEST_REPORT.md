## 功能交付

- 首次使用空白表单确认真实年龄、身高、体重、活动量、目标和日期后，生成首周 49 项任务。确认前不以示例体重或目标生成个人计划；旧数据保留，旧资料需要明确确认。
- 首页先展示目标、累计、运动目标/已记录时长、三个快捷入口、本地即时反馈、具体三餐及运动步骤。完整表单在可滚动模态弹窗中；移动导航为今日、日历、趋势、我的，加中间记录入口。
- 同一天允许多次称重；新增新 ID，编辑只更新原 ID。时段、可选时间和进食/排便状态纳入记录；旧字段缺失明确显示未注明。
- 主趋势优先晨起空腹，进食/排便条件分组，同条件同日取最早一条作代表，其余测量全部保留。没有晨起记录时使用标明条件的旧记录/同条件组，不混算。营养计算采用过去七个日历日的平均，不是最近七次测量。
- 展示静息能量、活动系数、温和缺口与目标依据；目标日期不扩大缺口。称重后只调整未完成、未手调的未来任务；超出支持范围时要求专业确认，不生成越界目标。
- 保存餐食/营养后即时更新累计、下一餐和后续任务；未知营养明确标注，不解释为零摄入。餐食照片写入后才关闭新增弹窗，失败时保留输入并提示。AI 仍需主动启用，不自动产生费用。
- 历史运动可编辑项目、时长、距离、强度、可选热量、感受和不适；保留原 ID，编辑与删除分开。运动/睡眠/疲劳会更新恢复建议，不按食物热量追加训练。
- 日历或历史日期进入同页详情：体重、营养、餐食/照片、运动、饮水/睡眠/身体状态、计划与实际、建议日志，保留各模块编辑入口。
- `coach_events` 追加日志并保存当日目标快照。历史修改不重写已完成计划或原目标；旧日期没有快照时显示未知，不拿当前资料冒充历史目标。
- ZIP/旧 JSON 保留称重上下文、日志、目标快照、任务和真实照片。恢复体重按 ID 合并，保留同日多条；预览、自动先备份、事务、版本冲突保护与不自动删图均保留。

## 剩余风险

- Oracle 的真实账号、会话、HTTP 数据服务、私有照片、跨设备同步和预算适配器仍待实现与验收；现有 SQL/端口是设计契约，不是生产后端。V2.1 不使用 Supabase 作为正式后端。
- 真实 DeepSeek 账号、识别准确率、额度与网络错误未实测，须用户明确同意并自行配置服务端 Key 后测试。不会自动调用 OpenAI 或其他付费服务。
- `body-parser`、`fast-uri`、`qs`、`zod` 的 4 项审计告警需要独立安全分支处理，本轮未擅自扩大依赖升级，不宣称可以直接部署公网。
- 实体手机、低内存设备、macOS 实体机解压和长期依从性未验证。本地配额保护、错误提示和 ZIP 不替代服务器备份。
- 通用食物与运动库不是医疗处方。疾病、孕哺、低体重、严重过敏或持续不适需要专业指导。

计算参考 [Mifflin–St Jeor 原论文](https://pubmed.ncbi.nlm.nih.gov/2305711/)，可持续方向参考 [CDC](https://www.cdc.gov/healthy-weight-growth/losing-weight/)。活动系数、温和缺口和保护边界是程序实现选择，不是论文提供的完整个体处方，不保证目标日期结果。

等待用户本地试用验收，不合并、不部署。
