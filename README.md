# 减肥计划 V2.1

每日个性化减肥教练：先看到今天的营养和运动目标，再记录真实执行并更新后续安排。本轮基于 `fe031ef`（含 Next.js 16.4.3），独立分支 `codex/v2-1-daily-coach`；不修改 main，不部署生产。V2 对照版保留在 `codex/v2-feedback-fixes`。

## 独立本地试用

技术栈：Next.js 16.4、React 19、TypeScript、Tailwind CSS、Recharts；本地记录和照片使用 IndexedDB，ZIP 使用 fflate。需要 Node.js >=22.13（建议 Node 24）。

```bash
npm ci
npm run preview:coach
```

本轮预览 [http://127.0.0.1:3008/](http://127.0.0.1:3008/)，V2 对照版为 3007。重新运行前可设置 PowerShell `$env:PREVIEW_PORT='3008'`；不指定时脚本从 3005 寻找空闲端口，以输出为准。只监听本机，使用该 worktree 独立的 `.next-coach`，强制清空外部数据库、AI 和 Google 凭证。不清空任何旧预览的浏览器数据。不同端口的 IndexedDB 不共享，需要用户通过完整 ZIP 自行选择迁移。

当前是无需账号的本地验收版本，不具备跨设备同步；清理浏览器数据可能丢失本地内容，请定期导出完整 ZIP。未配置 AI 时计划、任务、手工饮食、营养累计和备份均可使用。

## 今日行动与周计划

- 新用户先在空白资料表中确认真实年龄、身高、体重、活动量和目标，再获得首周 49 项安排；不使用未经确认的示例体重或目标。
- 首页显示进度、下一项和具体下一餐建议。每项任务有时间、份量/时长、操作步骤、安排原因、完成标准及可靠学习资料。
- 餐食可替换；任务可完成、跳过、跨日期/时间重新安排，运动可改为恢复。完成餐食时只有明确确认真实进食，才加入通用营养粗估；拍照不会自动调用 AI。
- 个人设置包含年龄、活动量、饮食类型、烹饪条件、设备、可用时间、过敏/身体限制。份量由确定性目标计算；通用食物数据不是特定品牌或医疗营养数据库。
- 周计划轮换食物、安排不连续的力量训练和恢复日。疲劳/身体不适只调整未完成训练；每周复盘可简化下一周，不因漏记而自动节食，也不覆盖已有下一周。
- 首页优先显示目标、确定性营养累计、三类快捷记录、具体三餐、运动步骤和本地计算提醒。完整录入表单在弹窗中，手机底部为今日、日历、趋势、我的及“+记录”。
- 每天可保存多次称重；只有编辑同一 ID 才更新原记录。保存时段、可选时间、进食和排便状态；旧记录缺字段时标明未注明。主趋势优先晨起空腹，进食/排便条件分组，同条件同日取最早一条，其余测量保留在每日详情。
- 日历或历史日期打开统一详情，同页查看体重、营养、照片、运动、身体状态、计划对比和追加式建议日志；历史运动可编辑，已确认任务不随历史修改静默覆盖。

目标速度、未成年人、体重过低、过敏与持续不适均有保守边界；这些不是诊疗或个体化医疗处方。设计、真实浏览器截图与验证详见 [V2.1 验收报告](docs/V2_1_TEST_REPORT.md)。

## 数据保护与完整备份

“我的”提供完整 ZIP 导出、查看备份内容、导入预览和空间估计。包含 `manifest.json`、`records.json`、真实 `images/` 文件及 SHA-256；周计划、任务执行、多次称重上下文、建议日志与目标快照均在备份中。

- 保留旧 JSON 兼容性，缺少实际照片的旧文件会明确提示。
- 恢复需用户确认，先下载现有完整 ZIP，然后合并；不自动清空历史数据或删除照片。
- 本地恢复使用 IndexedDB 事务与版本冲突检查，失败不静默覆盖；物理保留的未关联照片也纳入导出。
- 旧 Base64 照片迁移先保留原始快照，确认事务成功后再切换。
- 不导出 API Key、登录凭证、Google OAuth 凭证或临时签名 URL。
- 照片压缩最长边 1200px、通常目标约 280KB，实际结果取决于图片；当前 ZIP 上限 200MB/10000 张，并非服务器账户容量。

## 自托管方向

**最终只使用用户自己的 Oracle Cloud，不使用 Supabase。当前还不是可直接部署的自托管生产版本。**

`NEXT_PUBLIC_DATA_BACKEND=local` 是默认值；仅填写旧 Supabase URL/Key 不会连接。旧适配器/SQL/回归测试暂时保留以保护旧数据，只有显式 `legacy-supabase` 才启用，而且不支持新增计划持久化，不应作为当前版本生产方案。

已提供独立 PostgreSQL 结构 `server/selfhost/schema.sql` 与服务契约 `server/ports.ts`。自有账号、会话、同源 API、私有服务器图片、乐观并发控制和服务器级备份仍需实现、联调与安全验收。详见 [自托管架构](docs/SELF_HOSTED_ARCHITECTURE.md)。

## AI 与 ChatGPT 连接边界

每日目标、任务、营养累计、基础推荐和周复盘不消耗 AI Tokens。DeepSeek 只处理用户主动发起的文字/餐食图片识别，逐项返回食物、份量和营养，结果保存到本地记录并复用。

默认 `npm run preview:coach` 会清空服务端模型密钥并保持零外部请求。只有用户明确选择测试时，才在当前终端设置 `DEEPSEEK_API_KEY` 并运行 `npm run preview:coach:ai`。测试接口只接受同源回环地址，限制请求大小、文字长度、调用间隔、每日次数、输出 Tokens 和超时；失败不重试、不切换 OpenAI。密钥没有 `NEXT_PUBLIC_` 前缀，不会写入 IndexedDB、日志或 Git。

不会自动调用 OpenAI 或切换其他付费服务。最终生产 AI 必须接入 Oracle 自托管账号、数据与预算服务；本地测试模式不是生产认证方案。Google 摘要同步与只读 MCP 的旧实现保留，但必须迁移到新账号体系后重新验收。默认不发送照片、健康备注和身份信息。
